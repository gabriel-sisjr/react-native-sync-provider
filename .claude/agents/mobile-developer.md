## Library Authoring Principles (Non-Negotiable)

1. **Named exports only** — never expose a default export. Consumers import individual functions: `import { enqueue, flush, useSyncQueue } from '@gabriel-sisjr/react-native-sync-provider'`.
2. **TypeScript is the public contract** — every public symbol has explicit types, exhaustive JSDoc/TSDoc, and `@example` blocks where helpful. `any` is forbidden in the public surface.
3. **Codegen-friendly spec, ergonomic facade** — the `*.nitro.ts` interface uses primitive-friendly shapes (Nitro supports rich object types, but keep payloads flat and Sendable-equivalent). Convert TS enums to strings before crossing the bridge when it improves portability.
4. **No business logic in `src/index.tsx`** — only re-exports + thin facade wrappers around `NitroModules.createHybridObject<SyncProvider>('SyncProvider')`. Helpers go to `src/utils/`, errors to `src/errors/`, hooks to `src/hooks/`.
5. **Fail loudly when the native module is missing** — provide both a non-throwing probe (`isNativeModuleAvailable`) and a throwing assertion (`assertNativeModuleAvailable`). Web/SSR fallbacks (`*.tsx` vs `*.native.tsx`) must throw a deterministic `SyncError` with `NATIVE_MODULE_UNAVAILABLE` rather than silently no-op.
6. **`noUncheckedIndexedAccess` is on** — every array/object index access must be narrowed before use. No `arr[0]!` shortcuts.
7. **Backwards compatibility per semver** — additive changes minor; breaking changes require a `BREAKING_CHANGES.md` entry and a migration guide.

- `enqueue()` JS→native round-trip: **< 3ms** on a mid-range Android (Snapdragon 7-gen) and < 1ms on iPhone 12+

## Implementation Standards

### Nitro Modules specifics
- The `*.nitro.ts` interface is the **single source of truth**. After every edit, run `yarn nitrogen` and commit only if the regeneration succeeds.
- Method signatures must use Nitro-supported types. Prefer flat objects and primitives. For collections, use `Array<...>`. For union types, use string literals (Nitro maps these to native enums automatically).
- Async-style work (HTTP dispatch, DB reads) must return `Promise<T>` from the spec — Nitro generates `async`/coroutine signatures on Swift/Kotlin sides.
- Events: prefer **listener registration via spec methods** (`addListener(eventName, callback)`) returning a subscription token, rather than `RCTEventEmitter`. This stays JSI-native and avoids the legacy event emitter overhead.

### Hooks ergonomics
- Every hook must clean up subscriptions in its `useEffect` return — no leaked listeners.
- Re-render only when the consumer-visible state changes (compare with shallow equality or selectors).
- All hooks accept a configuration object (never positional arguments past the first) for forward-compatibility.
- Hooks must work both with and without the optional `<SyncProvider>` context provider.
- React 18+ `useSyncExternalStore` is the preferred pattern for hooks that mirror native event streams.

### TS facade conventions
- The facade in `src/index.tsx` lazily resolves the HybridObject **once per process** (memoized), and re-throws a wrapped `SyncError` if the native module is unavailable.
- All public functions accept TS enums as input; conversion to string (or other Nitro-native shape) happens in `src/utils/<mapper>.ts` before the JSI call.
- All public functions return rich TS types — never raw native shapes. If the spec returns `string`, the facade narrows/parses to a typed object.

### Offline-first design (the heart of the library)
- Native side owns the queue. JS is a thin client.
- `enqueue` returns immediately with the item id (ULID generated in JS for idempotency). Persistence is fire-and-forget on the JS side; failures surface via the next `getPendingItems` / `sync-event`.
- Default retry policy (exponential backoff + jitter, 5 attempts, retryable HTTP codes) is enforced in native. JS-side `ShouldRetryFn` is an optional override that **only runs when the app is alive**.
- Connection state is mirrored from native to JS via a single SharedFlow / Combine stream — never polled from JS.
- Background dispatch (BGTaskScheduler / WorkManager) is owned by native; JS can only enable/disable and configure intervals.

## Development Workflow

### Before implementation
1. Run `yarn typecheck` to confirm clean baseline.
2. Read `src/SyncProvider.nitro.ts` and `nitro.json`. Note the autolinking class names — they must match Swift/Kotlin implementations exactly.
3. Check `IMPLEMENTATION_ROADMAP.md` for the current phase and gate (M1–M6).
4. Confirm whether the change is an additive minor or a breaking semver bump.

### During implementation
1. Edit the `*.nitro.ts` spec **before** any other code, then run `yarn nitrogen`.
2. Add or update TS types in `src/types/` (consumer-facing) and helpers in `src/utils/` (internal).
3. Wire the JS facade in `src/index.tsx` with full JSDoc and `@example`.
4. Add or update React hooks in `src/hooks/` if the change is consumer-visible.
5. Update the `*.native.tsx` and `*.tsx` (web fallback) pair when introducing platform-extension files.
6. Update example app screens in `example/src/` to exercise the new path.

### After implementation
1. `yarn typecheck && yarn lint && yarn test` — all must pass.
2. `yarn prepare` — verify the bob build emits clean ESM + d.ts.
3. Run the example app on iOS and Android, exercising offline / online / airplane-mode paths.
4. Update README, API reference, and (if applicable) `BREAKING_CHANGES.md` and `CHANGELOG.md`.
5. Verify coverage did not regress (target ≥70% lines on `src/utils/`, `src/hooks/`, `src/errors/`, `src/index.tsx`).

## Testing Methodology

- **Unit (Jest)**: utils, hooks (with `@testing-library/react-native`), facade with native module mocked at the `NitroModules.createHybridObject` boundary.
- **Integration (Jest)**: offline→online queue flush, retry until max attempts, error propagation paths, AppState transitions.
- **Native interop (manual + example app)**: simulate airplane mode, force-quit, OS-killed background revivals.
- **Type tests (`tsd` or `expectTypeOf`)**: ensure the public surface stays stable; deliberate breaking changes must update these.
- Never rely on real network in unit tests — mock `URLSession` / `OkHttpClient` at the native boundary in integration scenarios.
